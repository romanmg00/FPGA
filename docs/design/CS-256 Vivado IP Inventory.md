# CS-256 Vivado IP Inventory

Which Vivado IP each build uses, where its settings live, and where it is instantiated. Checked on 4 November 2026 against the commits named below. Roman's rsws08 project could not be inspected, so anything about it is marked.

**The only IP core any build uses is the Clocking Wizard (`clk_wiz` 6.0).** No build uses Block Memory Generator: the memories are inferred from SystemVerilog (see [Memories](#memories-no-ip)).

## Rule: use the IP Vivado generates

Every Clocking Wizard in a synthesized build must be generated by Vivado from its IP Catalog. Do not replace one with a hand-written module, even one with the same name and ports.

- **`clk_wiz_0` and `clk_wiz_1` are instance names, not catalog items.** In the catalog, choose **Clocking Wizard** (`xilinx.com:ip:clk_wiz`) and set the Component Name, or use `create_ip` as `proyecto_final/build_game_top.tcl` does.
- **Settings must have a known source.** When the owner's `.xci` is unavailable, a regenerated Wizard is still real IP, but its settings are inferred. Say so, record them, and confirm them with the owner. `clk_wiz_1` below is in that state.
- **Stand-ins are for simulation only.** `proyecto_final/sim_clocks/` holds ideal clocks with the Wizards' names, so a bench can run quickly. They never go into synthesis, and a bench that uses them does not test the Wizards.
- **A direct `MMCME2_BASE` is not a substitute.** The one in `prototypes/vga_106mhz/` is an experiment. Using a primitive in the game needs an ADR. It also has no Wizard to define the board clock, so it adds `prototypes/vga_106mhz/game_top_trial.xdc`.
- **The build checks this three ways, and stops if any fails.** No design file may define a module named `clk_wiz_*`; each Wizard must be an IP object from the `clk_wiz` catalog entry; and each instance must have the generated `inst/mmcm_adv_inst` structure with one `MMCME2_ADV`. Together these catch a hand-written Wizard in the design, but they are not a formal proof, so reviewing the sources still matters.

## `game_top` (the milestone build)

`proyecto_final/game_top.sv` is the top in PR 11 (`v4/moving-block`, `e5407d8`) and in `v4/moving-block-fixes`.

| Instance | Purpose | Instantiated at | Settings in the repository |
|---|---|---|---|
| `clk_wiz_0`, `u_clk` | `clk_pix`, from the 100 MHz board clock | `game_top.sv` | PR 11: `proyecto_final/ip/clk_wiz_0/clk_wiz_0.xci`. Fixes branch: created by `proyecto_final/build_game_top.tcl`, which stops unless M, D and O match that `.xci` |
| `clk_wiz_1`, `u_clk1` | 5 MHz base for the `clk_juego` divider, from `clk_pix` | `game_top.sv` | **PR 11: none.** Fixes branch: created by `proyecto_final/build_game_top.tcl` |

Settings as built with Vivado 2025.2 on 4 November:

| Setting | `clk_wiz_0` | `clk_wiz_1` (regenerated) |
|---|---|---|
| Input frequency | 100.000 MHz | 83.456 MHz |
| Input source | `Single_ended_clock_capable_pin` | `No_buffer`, driven by `clk_pix` |
| Requested output | 83.46 MHz | 5.000 MHz |
| **Achieved output** | **83,455,882 Hz** | **4,999,995 Hz** |
| M / D / O | 28.375 / 4 / 8.500 | 44.125 / 6 / 122.750 |
| Reset and locked ports | Off | Off |

The divider then toggles `clk_juego` every 41,667 cycles of the 5 MHz clock: 4,999,995 Hz / (2 × 41,667) = 59.9995 Hz.

### Open problems

- **`clk_wiz_1.xci` is not in the repository.** PR 11's text says it is on rsws08. PR 11 cannot be built from a clean checkout without it. The settings above were inferred from `game_top.sv` and PR 11's text, so Roman's real values may differ, and any bitstream built here is not byte-for-byte his.
- **`clk_wiz_0.xci` is not portable as committed.** It records Vivado 2020.2 (`RUNTIME_PARAM.SWVERSION`), was customized for another part (`PROJECT_PARAM.DEVICE` is `xc7vx485t`), and writes outputs to `../../../../DigitalDesignsFinalProject.gen/`. Vivado 2025.2 reports it as locked and upgrades it from revision 6 to 17. Its frequency settings survive the upgrade. Adding it with `add_files` from another location failed in one build, because the output path falls outside the run folder; `import_ip` works. The fixes branch keeps this file for Roman's project but its build no longer reads it, which removes the upgrade's critical warning.
- **The Vivado version on rsws08 is not confirmed.** The `.xci` suggests 2020.2. A `.xci` written by 2025.2 may not open there, which is why the fixes branch creates `clk_wiz_1` from Tcl. That script has only been run on 2025.2.
- **Whether a second Wizard stays is open** in issue #10. [ADR 0002](../adr/0002-follow-ta-divided-game-clock.md) is the accepted decision until a later ADR replaces it.

## Rules

- Record **achieved** frequencies, not requested ones.
- Prefer creating a Wizard from Tcl with its settings written down. A committed `.xci` is tied to the Vivado version and project that made it.
- When a build adds, removes or changes an IP, update this note in the same change.
- To check a build, read its `<name>-frequency.txt` and `<name>-properties.txt`, or run this in Vivado after opening the project: `report_property [get_ips <name>]`.
